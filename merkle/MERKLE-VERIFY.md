# 单文件零信任验证（Merkle Proof）

## 这是什么

私有仓的 `MANIFEST.sha256` 有 **360** 条记录。原先要验证"某个文件是否在清单里"，必须拿到全部 360 条逐条比对。

现在改用**默克尔树**：给出一个根哈希 + 一份 **9 步**的审计路径，任何人都能验证**单个文件**属于该根——不需要下载整个清单，也不需要信任我们。

## 不需要的信任

- 不需要知道我们是谁
- 不需要访问私有仓
- 不需要联网
- 不需要安装任何第三方库（只要 Python 3 标准库）

## 三步验证

```bash
python3 verify_merkle.py merkle/proof_merkle_probe.py.json engine/merkle_probe.py
```

输出应为：

```
✅ 文件哈希匹配 20be5fcd11eb73a0…
✅ 审计路径成立（9 步）
✅ 归属于 MERKLE ROOT 78134b892dc9…
```

## 算法（可自行复核）

```
leaf = SHA256(0x00 || (路径 + '\0' + 文件sha256))
node = SHA256(0x01 || left || right)
root = 沿审计路径逐层合并所得
```

`0x00` / `0x01` 是域分离前缀，用于防第二原像攻击（RFC 6962 的加固做法，也是比特币默克尔树的安全版本）。

叶子同时绑定**路径**与**文件哈希**，因此改文件名也会导致验证失败。

## 已验证的反例

| 攻击 | 结果 |
|---|---|
| 改文件内容一个字节 | ❌ 文件哈希不符 |
| 改证明里的文件名 | ❌ 路径不成立 |
| 拿另一个文件配这份证明 | ❌ 文件哈希不符 |

## 本仓公开什么、不公开什么

| 公开 | 不公开 |
|---|---|
| 根哈希 | 360 条文件清单 |
| 个别文件的证明 | 其他文件的存在与名称 |
| 验证器代码 | 文件内容 |

**局部可验证不需要公开全量清单。** 你拿一个文件 + 一份证明 + 一个根，就能证明"这个文件是真的"；但你看不到根里还有哪些其他文件。这是隐私与可验证性的平衡点。
